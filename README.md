# Rezeptbuch

A single-page recipe app built with **vanilla JavaScript + Vite** (no framework).

- **Search by ingredients** — type what you have at home and find matching recipes (your German input is translated to English on the fly before searching).
- **Discover** — a daily, handpicked set of random recipes you can filter by cooking time.
- **Recipe detail** — ingredients with a checkable shopping list, step-by-step instructions, nutrition facts and diet tags. When you open a recipe from a search, the ingredients you already have are pre-ticked.
- **AI recipe generator** — turn your ingredients into a brand-new recipe for a given occasion, generated by the Groq LLM API and rendered in an "Apple Intelligence"-style panel.

The app uses two external APIs: **Spoonacular** (recipe search/detail/random) and **Groq** (`llama-3.1-8b-instant`, for ingredient translation and recipe generation).

## Setup

```bash
# 1. Clone
git clone <your-repo-url>
cd rezept-finder

# 2. Install dependencies
npm install

# 3. Configure your API keys
#    Copy the example env file and fill in your own keys:
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
```

Then edit `.env`:

```
VITE_SPOONACULAR_KEY=your_spoonacular_api_key_here
VITE_GROQ_KEY=your_groq_api_key_here
```

Get free keys at [spoonacular.com/food-api](https://spoonacular.com/food-api) and [console.groq.com](https://console.groq.com).

```bash
# 4. Start the dev server (http://localhost:5173)
npm run dev
```

Other scripts:

```bash
npm run build     # production build → dist/
npm run preview   # preview the production build locally
```

## ⚠️ A note on the API keys

These keys are **`VITE_` variables, which means they are client-side only** — Vite bundles them directly into the JavaScript that ships to the browser. **Anyone using a deployed build can read them.** That's fine for local development and demos, but **not** for a real public deployment.

For production you should put the keys behind a small **backend proxy** (a serverless function or a tiny Node/Express server) that holds the keys server-side and forwards requests to Spoonacular and Groq. The frontend then calls your proxy instead of the APIs directly.

Note also that the dev server proxies `/spoonacular/*` → `https://api.spoonacular.com/*` (see `vite.config.js`) to avoid CORS. **This proxy only exists in `npm run dev`** — a production deployment needs the same proxy replicated server-side.
